# UI consistency and responsive review

Reviewed against the examination workspaces at baseline `8931d89` on 17 November 2026.

## Scope and design conventions

Work proceeded through head teacher management pages, deputy management pages, DoS mark review, and class teacher pages. There is one deputy head teacher; no separate deputy-class-teacher role was introduced.

- Compact page headings replace oversized decorative banners.
- Restrained slate borders, solid panels, small corner radii, and consistent sky actions follow the examination workspace direction.
- Summary ribbons show readable labels and values; missing marks retain their existing pending/null behavior.
- Phone and tablet learner cards expose guardian details and profile/contact actions without requiring a wide directory table.
- Phone fee cards keep all three term inputs and a per-level save action together. Larger screens retain the fee matrix.
- Register rows give names their own line on phones and show full Present/Absent/Excused/Late labels with 44px touch targets.
- Tables scroll inside bounded, keyboard-focusable regions. Scrollable section controls have section labels rather than table labels.
- Shared dialogs use the available dynamic viewport height, scroll internally, support Escape, contain keyboard focus, and restore focus when closed.
- The mobile navigation is hidden from focus/accessibility while closed, closes on route changes or Escape, and uses the dynamic viewport height.

Reusable pieces live in `apps/web/src/components/WorkspaceHeader.tsx`, `WorkspaceStats.tsx`, and the `workspace-*` component styles in `apps/web/src/index.css`.

## Browser verification

Used the local React frontend and local Express application against the owner-confirmed development database. The preview API skipped startup DDL. The four supplied account types were signed in through the normal password/OTP flow; passwords and tokens are not stored in this report.

All routes below were loaded and measured at **360×800**, **768×1024**, and **1366×768** CSS pixels. The final measurements covered 21 distinct routes / 63 route-size combinations, with `document.documentElement.scrollWidth <= window.innerWidth` throughout.

| Area | Routes |
| --- | --- |
| Head teacher | `/settings`, `/staff`, `/admissions`, `/letters`, `/fee-structures`, `/finance` |
| Deputy | `/inventory`, `/leave-requests`, `/attendance`, `/timetable`, `/allocations` |
| DoS and school analysis | `/mark-review`, `/exams`, `/marking-allocations`, `/school-results`, `/subject-performance` |
| Teaching and class oversight | `/my-learners`, `/class-register`, `/class-exam-progress`, `/marks-entry`, `/class-performance` |

Additional interaction checks:

- Shared staff invitation dialog at tablet size: bounded height, internal scrolling, Escape dismissal.
- Inventory item dialog at phone size: bounded width and height.
- Learner profile/contact drawers at 360px: full-width presentation and working panel/close controls; no messages sent.
- Register attendance controls: full text labels and measured 44px height at phone width.
- Marksheet drawer: full phone width; locally scrollable loading and entry tables.
- Mobile navigation: open, route selection/sign-out, and expanded-state behavior.
- Fee structures: laptop light mode, phone light mode, and phone dark mode screenshots; dark preference restored afterward.
- Class Performance inspected with both the Grade 4 teacher and Grade 9 leadership assignment, including the national-cohort layout.

The review found and corrected two existing responsive constraints: Class Performance's nonshrinking controls/summary text expanded the document beyond phone/tablet widths; the marksheet drawer unnecessarily reserved a left gutter on phones. Its loading table is now scrollable as well.

## Limits and deferred work

These are browser viewport checks, not tests on physical Safari/iOS or Android devices. They do not establish every possible data length, empty/error state, keyboard configuration, or print-driver result.

No admissions, fees, marks, allocations, invitations, SMS, or other business records were submitted to exercise write actions. Normal sign-in updates authentication metadata. Backend authorization, mark-lock transitions, allocation endpoint mismatches, finance correctness, schema migrations, and the broader test suite remain separate work; no backend/schema implementation was changed in this UI pass.

When extending a page, verify phone/tablet widths using loaded content rather than only its skeleton. Keep wide tables locally scrollable, and avoid combining nonshrinking flex groups with long native select options.
